# Start Here: Churn Prediction Project (VS Code / Windows)

This package restores the original folder layout and includes a repaired validation script, lean dependency files, a model preflight check, and a local-only API run path.

## 1. Open the correct folder

1. Extract the ZIP file.
2. In VS Code, choose **File → Open Folder**.
3. Select the extracted folder named `churn-prediction-final` (the folder containing `README.md`, `config.yaml`, `api`, `src`, and `deployment`).
4. Open **Terminal → New Terminal**. Confirm the terminal is at the project root.

## 2. Create the environment (recommended: Python 3.11)

The supplied README specifies Python 3.11. In PowerShell, run these commands one at a time:

```powershell
py -3.11 --version
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks environment activation, use the environment's Python directly instead:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Do not install packages globally. The requirements intentionally keep scikit-learn at **1.9.0**, matching the supplied serialized model and preprocessor.

## 3. Verify the supplied model and files

```powershell
python check_project.py
```

Expected final line: `Project preflight check completed.` The script loads the supplied deployment model and preprocessor and performs one prediction. If you did not activate `.venv`, use `\.venv\Scripts\python.exe check_project.py`.

## 4. Run the API

```powershell
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Open these addresses in your browser:

- `http://127.0.0.1:8000/` - service status
- `http://127.0.0.1:8000/health` - health check
- `http://127.0.0.1:8000/docs` - interactive API testing page

Keep the terminal running while using the API. Press `Ctrl+C` to stop it. Alternatively, double-click `run_api.bat` after setup.

## 5. Run the automated tests

Open a second VS Code terminal at the project root, activate `.venv`, and run:

```powershell
python -m pytest tests -q
```

The included API and performance tests should pass when dependencies are installed and the supplied deployment artifacts are present.

## 6. Run the full MLOps lifecycle locally (optional)

The MLOps pipeline additionally uses Pandera and MLflow, which are included in `requirements.txt`. Set a local SQLite tracking store and run from the project root:

```powershell
$env:MLFLOW_TRACKING_URI = "sqlite:///mlflow.db"
python .\src\mlops_pipeline\churn_prediction_pipeline.py --force --skip-deployment
```

- `--force` runs training stages even though the supplied `new_churn.csv` batch is already recorded in the dataset lineage.
- `--skip-deployment` skips Docker/Kubernetes deployment but still runs the model lifecycle and inference stages. Docker Desktop and Kubernetes are therefore not needed for this local workflow.
- The configured quality gate requires recall of at least `0.70`. If a newly trained model does not meet that threshold, the pipeline correctly stops at the quality gate. That is a model-quality decision, not a Python installation error.
- MLflow starts with a fresh local registry because the original local registry database and run artifacts were not included in the handout.

To run the deployment stage, omit `--skip-deployment` and make sure Docker Desktop and Kubernetes are installed and running, and that `kubectl` is configured.

## Important notes about the supplied ZIP

- The supplied ZIP was a flat handout, not a runnable folder tree. This repaired package restores files to the paths in `FILE_PLACEMENT_MAP.csv`.
- `src/validate_outputs.py` had a syntax error (`{4`); it has been repaired and now checks array dimensions and non-finite values.
- `api/__init__.py` was absent and has been recreated as an empty package initializer.
- Two historical model files (`models/churn_full_pipeline.pkl` and `models/churn_model.pkl`) were not present in the ZIP. The latter is generated by the MLOps training stage. The API does **not** need either historical file because it uses the supplied `deployment/model.pkl` and `deployment/preprocessor.pkl` bundle.
- A completely error-free run cannot be guaranteed on every PC: Python version, internet access during package installation, antivirus restrictions, and optional Docker/Kubernetes services are machine-specific. The supplied API was smoke-tested, and the included API/performance tests were run successfully in the repair environment.
